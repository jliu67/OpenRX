## Finding

**Monero's current released mainnet consensus target is RandomX v1.** This is an inference from the latest official stable release and its consensus code, corroborated by the observed upstream master snapshot. It is not a direct live-chain measurement. The released mainnet schedule contains no RandomX v2 activation height/date. The official roadmap still places RandomX v2 under Future / Coming Soon without a date.

The October 5, 2026 activation mentioned in the FCMP++ beta release is a **separate beta stressnet fork from testnet**, at height 3,102,800. It does not establish mainnet activation. RandomX library v2.0.1 availability also does not establish activation.

## Consensus path checked

In released Monero `src/crypto/hash-ops.h:95`, `RX_BLOCK_VERSION` is 12. `src/cryptonote_core/cryptonote_tx_utils.cpp:717–748` selects `rx_slow_hash` when the block major version is at least 12. `src/crypto/rx-slow-hash.c:408` obtains implementation flags and calls the pinned RandomX API; there is no algorithm-v2 flag or hardfork-v2 branch. The bundled RandomX `src/randomx.h:42–52` enum contains only the legacy flags. The mainnet schedule is installed in `src/cryptonote_core/blockchain.cpp:337–338`, and block-version checks appear at lines 1890 and 4089. These sources connect the released schedule to the actual PoW path rather than treating a library release title as network evidence.

In beta 3.0, `src/cryptonote_config.h:213` defines RandomX v2 at HF17. `src/cryptonote_basic/cryptonote_format_utils.cpp:2022–2045` selects variant 2 at HF17. Its testnet table sets HF17 at 3,102,800 and HF18 at 3,103,520. **The beta file's mainnet HF17/HF18 entries at 2,689,609/2,689,610 are explicitly mock test values.** They are not a published mainnet upgrade schedule. A beta 3.1 lightweight tag was also observed at `b13ab0cabadeb301b2ce5282b077945e9ab3a7ba`; its audited schedule/configuration/hash-selection files match beta 3.0 byte for byte. No beta 3.1 release API object was found.

Beta HF17 also enables a PoW commitment step after the raw RandomX hash. OpenRX's existing raw v1/v2 API controls therefore do not by themselves establish complete beta Monero block-PoW compatibility.
