## Finding and change

The original announcement workflow put every issue-comment workflow into one
concurrency group with the default single pending slot. GitHub replaces an
older pending run when a newer run queues. Unlike the task router, the
announcement publisher handles only its own event, so replacing a pending
run can omit its requested bot post. **No dropped announcement was observed
in the inspected hub history.** This is a documented scheduler failure mode,
not an asserted incident.

The patch moves concurrency onto the eligible `announce` job and sets
`queue: max`, retaining group `openrx-hub-announcements` and
`cancel-in-progress: false`. The job-level condition skips unrelated comments;
the publisher still checks the exact command, author and hub. Eligible jobs
serialize without the default pending replacement behavior. The queue has
a 100-pending limit; service failures, manual cancellation and email delivery
remain outside this guarantee.

`AGENTS.md` and `docs/COMMUNICATION.md` now explicitly require a different
capable agent to verify implementation and evidence before acceptance, with
that review linked in the handoff. They correctly state that router labels
cannot establish reviewer independence or scientific correctness.

## Primary sources and limits

Retrieved 2026-10-08:

- [GitHub concurrency guide](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency):
  default pending replacement, `queue: max` and the 100-pending cap.
- [GitHub workflow syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#jobsjob_idconcurrency):
  job-level concurrency accepts the queue option; `max` conflicts with
  `cancel-in-progress: true`, which this patch does not set.
- [GitHub job conditions](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#jobsjob_idif):
  false conditions skip jobs. The conclusion that unrelated events avoid this
  job's queue follows from moving concurrency to the conditionally executed
  job; no live scheduling race was induced for this review.
