## Verified gem5 failure mechanism

- [Push run 37805005108](https://github.com/jliu67/OpenRandomX/actions/runs/37805005108), job 113406864380, and [PR run 37805009018](https://github.com/jliu67/OpenRandomX/actions/runs/37805009018), job 113406877620, both failed.
- The pinned source checkout and SCons build progressed through C++ translation units; neither log shows a fatal source diagnostic before cancellation. The workflow explicitly runs `timeout --signal=TERM --kill-after=30s 45m scons build/RISCV/gem5.opt -j2`. Both ended with `Process completed with exit code 124` and `scons: Build interrupted`.
- **All later steps were skipped:** cross-compiling runtime controls, guest firmware/kernel/disk preparation, in-simulator Linux boot, SIGILL handling, JIT flush/reexecution and full RandomX. This failure is **not a failed runtime-correctness test**; the runtime was never reached.
- Both push and PR triggers repeated a large clean source build at the same branch head, consuming approximately **90 GitHub-hosted runner minutes combined** without reaching the boot gate. Usage charges depend on repository/account settings; no paid resource was deliberately provisioned here.
- Both jobs preserved bounded partial build logs/artifacts. Passing offline wrapper tests are useful but cannot establish successful gem5 execution.

**Mitigation communicated:** [PR #18 inspector comment](https://github.com/jliu67/OpenRandomX/pull/18#issuecomment-6064815430) and [task #16 note](https://github.com/jliu67/OpenRandomX/issues/16#issuecomment-6064817805). Keep the existing session claim; do not rerun unchanged full builds. Prefer one trigger for the expensive job, an isolated source-pinned build stage with cached/preverified binary artifacts (including digests and provenance), memory/disk/runtime checks and explicit boot/test evidence. Any alternate binary or cached build must preserve the selected version and runtime semantics. **Do not claim M3 or M4 completion until exact selected runtime and RandomX gates actually pass.** This inspector did not modify the agent's branch or workflow.
