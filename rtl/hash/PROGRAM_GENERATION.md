# Native AES program generation

`randomx_program_generation.v` implements pinned RandomX `fillAes4Rx4<true>`
using the existing `randomx_aes_round` and licensed secworks S-boxes. The native
`randomx::Program` occupies 3,200 bytes: 128 entropy bytes followed by 384
8-byte instructions. This is the pinned maximum Program layout used by v2.

A request captures its 512-bit seed and 16-bit tag. Four independent 128-bit
lanes retain private recurrence state. Lanes 0/2 decrypt; lanes 1/3 encrypt.
Each lane uses four raw AES rounds, with native keys 0..3 for lanes 0/1 and
keys 4..7 for lanes 2/3. The shared round unit computes one round per clock;
the fourth result is offered as a tagged 16-byte output. Accepted outputs
advance byte address and recurrence together. An output stall preserves the
offered bytes/address/tag and the final round state.

Unlike `fillAes1Rx4`, native `fillAes4Rx4` leaves its input seed unchanged.
The component consequently has no mutated-seed response. Completion returns
only the accepted request tag; it remains held until acknowledged. Reset and
cancel immediately suppress handshakes and invalidate private control state.
Previously accepted external outputs remain the receiver's responsibility.
`OUTPUT_BYTES` accepts multiples of 64 from 64 through 3,200; invalid values
fail elaboration. The default produces a complete native Program.

## Connected ownership

`randomx_prepared_hash_lifecycle` opts in through `HARDWARE_PROGRAM=1`.
The default `0` retains the external generation path for historical
reproduction. `HARDWARE_FILL` remains a separate option.

For each internal metadata request, hardware captures the actual current seed:
the initial fill's post-fill seed for program 0, then the accepted register-file
BLAKE2b seed for each successor. All 200 tagged output beats must arrive in
order, followed by the matching completion, before entropy metadata is offered
to preparation. A private logical 3,200-byte image holds the 128 entropy bytes
and 384 instructions. Existing preparation consumes these instructions through
an internal tagged, held fetch response. A new program cannot replace an image
while a fetch response is pending. Cancellation/error invalidates image
ownership and pending replies; stored bytes need not be cleared to become
inaccessible.

External metadata and program request-valid pins are suppressed in hardware
mode. Removed provider replies are drained and cannot supply instructions or
raise matching provider faults. Native generation callbacks in the testbench
are assertion-only: they compare all generated bytes and internal fetches,
and are counted separately from live provider calls.

Outer phase 7 records generation, including start, return and metadata delivery.
Nested generator phases partition that complete stage. The 800 AES compute
clocks for one Program are therefore distinct from connected stage overhead.
The existing instruction-image load count describes internal buffer traffic
in this mode. Complete stage sums must still equal the observed hash clocks.

## Reproduction and limits

Inside an admitted serial payload:

```sh
python3 -B scripts/test_program_generation.py --output FRESH_EXTERNAL_DIRECTORY --synthesize
```

Executed source `0d70bf0cb3031ff5a3cdc26eda88a17254e89d18` passed 15 native
cases, 44 RTL modes (ten complete 3,200-byte profiles), 24 bounded mapped modes,
seven malformed-native cases and four invalid parameter guards. Full-image
availability measured 800 ideal clocks or 1,000 with 200 output stalls. Default
Yosys/ABC mapping measured 36,836 generic cells, 540 flop cells and zero latches.
Mapped differential checks cover 256 output bytes; default mapping and complete
native RTL image checks are separate evidence.

These mapping counts include only the new generator and reused AES round.
They exclude the connected image buffer, preparation, executor and physical
memories. They establish no process, MHz, physical area, power, ASIC efficiency
or architecture selection. Host input BLAKE2b and native Light dataset/device
service remain boundaries. A bounded connected run is separate from a new
default eight-program by 2,048-iteration measurement.

Connected tested code `8100bee97bd592767764e5c9a8d3caa3aa2d7183` passes two-program × one-iteration ideal/stalled completion and focused generation cancellation/initialization errors. Ideal Icarus/Verilator ledger, trace, digest and all native corpus files agree. Measured totals are 534,012 ideal and 1,583,537 stalled clocks; generation contributes 1,606 clocks for two programs, including control/metadata overhead. [Exact evidence](../../docs/validation/program-generation-20261016/README.md) records limits and reproducibility.
